# iOS ANCS 통합 0.6.15 / 펌웨어 0.4.0

## 바뀐 점 (펌웨어 0.4.0)

- **MQTT 서버 쪽 장애는 재시도만 합니다.** MQTT 서버에 한 번 연결된 설정은 기억해 둡니다. 그 뒤 브로커가 꺼지거나 재시작하거나 네트워크가 끊기면 설정 AP를 열지 않고 5초, 15초, 30초, 이후 60초 간격으로 계속 다시 연결합니다.
  - 0.3.9는 Wi-Fi가 정상이어도 MQTT가 끊기면 설정 AP를 바로 열었습니다. 그래서 브로커가 재시작하는 동안(예: Mosquitto 애드온 업데이트) SSID에서 알 수 있는 비밀번호로 근처 누구나 접속해 설정을 바꿀 수 있었습니다.
- **설정 거부는 10분을 기다립니다.** 연결된 적이 있는 설정을 브로커가 계속 거부하면(아이디·비밀번호·권한·Client ID) 10분이 지난 뒤에만 설정 AP를 엽니다. Home Assistant의 Mosquitto 애드온은 Home Assistant가 재시작하는 동안 로그인을 거부합니다.
- **새 서버로 비밀번호를 보내지 않습니다.** 설정 포털에서 MQTT 서버 주소나 포트를 바꾸면 저장된 MQTT 비밀번호를 쓰지 않습니다. 아이디가 있는데 비밀번호 칸이 비어 있으면 다시 입력하라는 안내가 나옵니다.
- **MQTT 연결 테스트 버튼을 고쳤습니다.** 지금까지는 눌러도 아무 동작을 하지 않았고, 이제 누르면 바로 다시 연결을 시도합니다.

## 바뀌지 않은 것

- 처음 설치, 한 번도 연결된 적이 없는 설정(오타)은 지금처럼 연결에 실패하면 설정 AP가 열립니다.
- Wi-Fi 45초 규칙, BOOT 3초(10분 동안 설정 AP), 설정 저장 뒤 10분 확인 창은 그대로입니다.
- 설정 AP 이름(`IOS-ANCS-SETUP-XXXXXX`)과 비밀번호(`ancs-xxxxxx`), Bluetooth PIN `123456`, 등록 창도 그대로입니다.
- MQTT 토픽과 Discovery, Home Assistant 엔티티, 저장된 설정 형식, 파티션 표도 바꾸지 않았습니다. 기존 기기는 설정과 iPhone 페어링을 유지한 채 앱 이미지만 바꿀 수 있습니다.
- Home Assistant 통합(HACS) 코드는 바꾸지 않고 버전만 0.6.15로 올렸습니다.

## 업데이트

- **펌웨어:** HACS는 펌웨어를 업데이트하지 않습니다.
  - 새로 설치할 때는 [설치 페이지](https://1bobby-git.github.io/HA-iOS-ANCS/)를 씁니다. 공장 초기화 이미지라서 기존 설정과 페어링이 지워질 수 있습니다.
  - 기존 기기를 업데이트할 때는 이 릴리스의 `.app.bin`을 각 칩의 `.json`에 적힌 앱 주소(`0x10000`)에만 쓰세요. 그러면 설정과 페어링이 유지됩니다.
- **Home Assistant 통합:** HACS에서 업데이트한 뒤 Home Assistant를 다시 시작합니다.
- **되돌리기:** v0.6.14 릴리스에 있는 펌웨어 0.3.9 이미지로 되돌릴 수 있습니다.

## 검증

- **호스트 C 테스트**(gcc): 리듀서 시나리오, MQTT 설정 지문, 서버 변경과 비밀번호 재입력, 병합 함수, 검증 표시 저장
  - 시나리오: 첫 설치, 6시간 브로커 장애, 재부팅 뒤 기억, 10분 거부, Wi-Fi 복구 뒤 브로커 장애, BOOT 창, 새 설정
- **저장소 테스트:** `tools/tests`, `tests`가 Home Assistant 2026.7.0과 2026.10.4에서 통과했습니다.
- **펌웨어 빌드:** GitHub Actions에서 ESP-IDF 6.0.2로 7종을 빌드했습니다. 그 결과물을 `package_firmware.py`로 패키징하고, `finalize_firmware_release.py`로 앱 ELF 지문을 대조했습니다.
- **실기기 Unity 테스트 앱:** 컴파일만 확인했습니다.
- **확인하지 못한 것:** 실제 보드에서의 Wi-Fi·BLE·MQTT 동작, 브로커 재시작 중 동작, NVS 쓰기, iPhone 알림 전달

## English summary

Firmware 0.4.0 remembers MQTT settings once they have connected (`mqtt_ok` in the provision partition). While the broker is down, restarting, or unreachable, the relay keeps retrying (5, 15, 30 s, then every 60 s) and no longer opens the setup AP. Firmware 0.3.9 opened it immediately on any MQTT drop. If the broker keeps refusing proven settings, the setup AP opens only after 10 minutes. Settings that never connected still open the setup AP on failure, and the Wi-Fi 45 s rule and the BOOT 3 s window are unchanged. The setup portal no longer reuses the stored MQTT password when the MQTT host or port changes, and the portal's MQTT test button now starts a connection attempt. Setup AP name and password, BLE PIN, topics, entities, stored settings and partitions are unchanged. The companion integration only bumps its version. Hardware behaviour was not tested.
