# iOS ANCS 통합 0.6.15 / 펌웨어 0.4.0

## 바뀐 점 (펌웨어 0.4.0)

- **MQTT 서버 쪽 장애는 재시도만 합니다.** MQTT 서버에 한 번 연결된 설정은 기억해 둡니다. 그 뒤 브로커가 꺼지거나 재시작하거나 네트워크가 끊기면 설정 AP를 열지 않고 5초, 15초, 30초, 이후 60초 간격으로 계속 다시 연결합니다.
  - 0.3.9는 Wi-Fi가 정상이어도 MQTT가 끊기면 설정 AP를 바로 열었습니다. 그래서 브로커가 재시작하는 동안(예: Mosquitto 애드온 업데이트) SSID에서 알 수 있는 비밀번호로 근처 누구나 접속해 설정을 바꿀 수 있었습니다.
  - TLS 인증서 오류도 브로커에 닿지 않은 것으로 보고 재시도만 합니다. 브로커 주소, 포트, 인증서를 바꾼 뒤에는 BOOT 버튼을 3초 눌러 설정 포털을 여세요.
- **설정 거부는 10분 동안 지켜봅니다.** 연결된 적이 있는 설정을 브로커가 응답하면서 10분 동안 매번 거부하면(아이디·비밀번호·권한·Client ID) 그때 설정 AP를 엽니다. 그사이 브로커에 닿지 않은 시도가 있으면 10분을 다시 셉니다. Home Assistant의 Mosquitto 애드온은 Home Assistant가 재시작하는 동안 로그인을 거부하기 때문입니다.
- **연결된 적이 있는 설정의 비밀번호를 새 주소로 보내지 않습니다.** 설정 포털에서 그런 설정의 MQTT 서버 주소나 포트를 바꾸면 저장된 MQTT 비밀번호를 쓰지 않습니다. 아이디가 있는데 비밀번호 칸이 비어 있으면 다시 입력하라는 안내가 나오고, 아이디도 비우면 비밀번호 없이 저장합니다.
  - 이 확인은 주소와 포트만 봅니다. TLS를 끈 MQTT에서는 설정 포털에 들어온 사람이 Wi-Fi를 자기 네트워크로 바꾸고 같은 브로커 주소로 응답하면 비밀번호를 받을 수 있습니다. 비밀번호를 지키려면 TLS와 CA 인증서를 쓰세요.
  - 아이디만 쓰고 비밀번호가 없는 새 브로커로 옮길 때는 두 번 저장해야 합니다. 먼저 아이디 없이 새 주소를 저장한 뒤 아이디를 넣어 다시 저장하세요.
- **MQTT 연결 테스트 버튼을 고쳤습니다.** 지금까지는 눌러도 아무 동작을 하지 않았고, 이제 누르면 바로 다시 연결을 시도합니다.

## 바뀌지 않은 것

- 처음 설치, 한 번도 연결된 적이 없는 설정(오타)은 지금처럼 연결에 실패하면 설정 AP가 열립니다. 고칠 때 비밀번호 칸을 비워 두면 저장된 값을 그대로 씁니다.
- Wi-Fi 45초 규칙, BOOT 3초(10분 동안 설정 AP), 설정 저장 뒤 10분 확인 창은 그대로입니다.
- 설정 AP 이름(`IOS-ANCS-SETUP-XXXXXX`)과 비밀번호(`ancs-xxxxxx`), Bluetooth PIN `123456`, 등록 창도 그대로입니다.
- MQTT 토픽과 Discovery, Home Assistant 엔티티, 저장된 설정 형식, 파티션 표도 바꾸지 않았습니다. 기존 기기는 설정과 iPhone 페어링을 유지한 채 앱 이미지만 바꿀 수 있습니다.
- Home Assistant 통합(HACS) 코드는 바꾸지 않고 버전만 0.6.15로 올렸습니다.

## 업데이트

- **펌웨어:** HACS는 펌웨어를 업데이트하지 않습니다.
  - 새로 설치할 때는 [설치 페이지](https://1bobby-git.github.io/HA-iOS-ANCS/)를 씁니다. 공장 초기화 이미지라서 기존 설정과 페어링이 지워질 수 있습니다.
  - 기존 기기를 업데이트할 때는 이 릴리스의 `.app.bin`을 각 칩의 `.json`에 적힌 앱 주소(`0x10000`)에만 쓰세요. 그러면 설정과 페어링이 유지됩니다.
  - 0.3.9에서 업데이트한 기기는 기억해 둔 설정이 없으므로, 0.4.0에서 MQTT에 처음 연결된 뒤부터 재시도 규칙이 적용됩니다. 그 전에 MQTT 연결이 실패하면 0.3.9처럼 설정 AP가 열립니다.
- **Home Assistant 통합:** HACS에서 업데이트한 뒤 Home Assistant를 다시 시작합니다.
- **되돌리기:** v0.6.14 릴리스에 있는 펌웨어 0.3.9 이미지로 되돌릴 수 있습니다.

## 검증

- **호스트 C 테스트**(gcc, Validate 워크플로에서 실행): 리듀서, MQTT 설정 지문, 비밀번호 규칙, 설정 병합, 검증 표시 저장
  - 리듀서 시나리오: 첫 설치, 6시간 브로커 장애, 재부팅 뒤 기억, 10분 연속 거부, 거부 뒤 브로커 장애, 거부 사이의 브로커 장애, 거부 뒤 Wi-Fi 장애, Wi-Fi 복구 뒤 브로커 장애, BOOT 창, 새 설정
- **실기기 Unity 테스트 앱:** 컴파일만 확인했습니다.
- **확인하지 못한 것:** 실제 보드에서의 Wi-Fi·BLE·MQTT 동작, 브로커 재시작 중 동작, NVS 쓰기, iPhone 알림 전달

## English summary

Firmware 0.4.0 remembers MQTT settings once they have connected (`mqtt_ok` in the provision partition). While the broker is down, restarting, or unreachable, the relay keeps retrying (5, 15, 30 s, then every 60 s) and no longer opens the setup AP; firmware 0.3.9 opened it on any MQTT drop. TLS certificate failures are retried the same way, so hold BOOT for 3 seconds after changing the broker host, port, or certificate. The setup AP opens for proven settings only after the broker has answered and refused every attempt for 10 minutes; an attempt that cannot reach the broker starts the 10 minutes again. Settings that never connected still open the setup AP on failure and still reuse the stored password when its field is blank. For settings that connected, changing the MQTT host or port no longer reuses the stored password. That check covers the host and port only: with TLS off, someone who reaches the portal can move Wi-Fi to a network that answers on the same address, so use TLS with a CA to protect the password. The portal's MQTT test button now starts a connection attempt. Devices updated from 0.3.9 follow the retry rule after their first successful connection on 0.4.0. Setup AP name and password, BLE PIN, topics, entities, stored settings and partitions are unchanged. The companion integration only bumps its version. Hardware behaviour was not tested.
