# iOS ANCS 통합 0.6.14 / 펌웨어 0.3.9

## 바뀐 점

- 통합 항목을 삭제하면 통합이 저장해 둔 마지막 알림(`.storage/ha_ios_ancs.<항목 ID>.last_notification`)도 지웁니다. 지금까지는 삭제한 뒤에도 알림 제목과 본문이 이 파일에 남았습니다. 언로드에 실패한 항목을 삭제할 때도 남은 구독을 멈추고 파일을 지웁니다.
- 0.6.13 이하에서 삭제한 항목이 남긴 파일은 활성화된 통합 항목이 하나라도 있으면 Home Assistant 시작 때(또는 항목을 추가하거나 활성화할 때) 지웁니다. 활성화된 항목이 없으면 이 정리가 실행되지 않으므로 `.storage/ha_ios_ancs.*.last_notification` 파일을 직접 지우세요. 파일을 지우지 못해도 통합 설정은 계속됩니다.
- 알림을 받고 2초 안에 다시 불러오거나 삭제하면, 아직 쓰지 않은 저장을 언로드 중에 마칩니다. 다시 불러오면 가장 최근 알림이 복원되고, 삭제한 파일이 나중에 다시 생기지 않습니다.
- `연결 복구 상태`와 `알림 수신 준비` 진단 엔티티는 1분마다 바뀌는 속성을 Recorder에 기록하지 않습니다. 대상은 `uptime_seconds`, `last_notification_uptime_ms`, `accepted`, `published_ack`, `dropped_*`, `wifi_retry_in_ms`, `mqtt_retry_in_ms`, `enrollment_remaining_seconds`입니다.
  - 펌웨어가 60초마다 상태를 보내면서 엔티티마다 1분에 한 번씩 속성 기록이 새로 쌓이던 문제입니다. 짧은 상태 기록은 지금처럼 남습니다.
  - 상태 화면, 템플릿, 자동화에서 보이는 현재 값은 그대로입니다. 같은 값의 기록은 MQTT 장치 상태 엔티티에 남습니다.
  - 연결 단계, 오류 코드, 알림 내용 엔티티의 기록은 바뀌지 않습니다.
- 테스트를 Home Assistant 2026.7.0(최소 지원), 2026.9.4, 2026.10.4에서 모두 통과하도록 고쳤습니다. CI는 2026.7.0과 2026.10.4를 함께 시험합니다.
- 0.6.13 배포에만 쓰던 워크플로를 삭제했습니다. 이 워크플로는 만료된 빌드 결과를 찾느라 이후 push마다 실패했습니다. 이미 반영된 일회성 로고 워크플로도 함께 삭제했습니다.
- README의 오래된 0.6.10 안내를 변경 이력 안내로 바꾸고, SECURITY.md를 실제 보안 정책으로 바꿨습니다.

## 바뀌지 않은 것

- 펌웨어는 0.3.9 그대로입니다. 첨부한 펌웨어 파일은 v0.6.13과 같은 파일이고 SHA-256도 같습니다. ESP32를 다시 플래시할 필요가 없습니다.
- 설치 페이지, 설정 AP 이름(`IOS-ANCS-SETUP-XXXXXX`)과 비밀번호(`ancs-xxxxxx`), Bluetooth PIN `123456`, 등록 창은 그대로입니다.
- 엔티티와 고유 ID, MQTT 토픽, 알림 이벤트, 최소 Home Assistant 버전(2026.7.0)도 그대로입니다.

## 업데이트

HACS에서 `iOS ANCS`를 업데이트한 뒤 Home Assistant를 다시 시작합니다. HACS는 통합만 업데이트하며 ESP32 펌웨어는 건드리지 않습니다.

## 검증

- 저장소 테스트 362개(`tools/tests`, `tests`): Home Assistant 2026.7.0, 2026.9.4, 2026.10.4 (Python 3.14)
  - 새 수명주기 테스트 13개 중 10개는 0.6.13에서 실패합니다. 대상은 삭제, 저장 대기 중 삭제·다시 불러오기, 설정 실패, 언로드 실패 뒤 삭제(쓰기 진행 중 포함), 비활성화 뒤 삭제, 소스 엔티티 방식, 예전 파일 정리, Recorder 제외입니다. 나머지 3개(알림 없는 다시 불러오기, 알림 내용 기록 유지, 파일 정리 오류 처리)는 바뀌면 안 되는 동작을 지키는 테스트입니다.
- 실제 Home Assistant 코어(pytest-homeassistant-custom-component, MQTT 모의 클라이언트, SQLite Recorder)에서 7개 시나리오를 확인했습니다. 시험한 버전은 2026.7.0과 2026.10.4입니다.
  - 확인한 시나리오: 설정, 알림 이벤트, 재시작 뒤 복원(새 이벤트 없음), 삭제 시 저장 파일 삭제, 저장 대기 중 삭제, 저장 대기 중 다시 불러오기, Recorder 기록 내용
  - 같은 시나리오 중 변경 대상 4개는 0.6.13에서 실패합니다.
- 확인하지 못한 것: 실제 ESP32와 iPhone, 실제 MQTT 브로커, 운영 중인 Home Assistant의 Recorder DB 크기 변화

## English summary

Companion 0.6.14 deletes the saved last notification when the config entry is removed, including after a failed unload, and at startup (with an enabled entry) it deletes files left by entries removed with earlier versions; a cleanup error never blocks setup. It also finishes a still-delayed save during unload, so a reload restores the newest notification and a removed entry leaves no file behind. The two connection diagnostic entities no longer record attributes that change with every 60-second status sample or notification (uptime, counters, retry waits), so the recorder stops adding an attribute row per sample; a short state row is still written. Live values are unchanged, and the MQTT device-status entity keeps that history. The tests now pass on Home Assistant 2026.7.0, 2026.9.4 and 2026.10.4, and CI checks 2026.7.0 and 2026.10.4. The one-off 0.6.13 release workflow, which failed on every later push, has been removed. Firmware stays at 0.3.9: the attached images are byte-identical to v0.6.13, and no reflash is needed. Hardware, iPhone and live-broker behaviour were not tested.
